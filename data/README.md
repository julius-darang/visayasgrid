# Data guide

This directory contains source inputs, prepared network tables, scenario tables and a historical provenance ledger. Read [SOURCES.md](SOURCES.md) before changing facts; use the [development guide](../docs/development.md) for rebuild commands.

## Ownership: where to edit

| File/location | Role | Editing rule |
|---|---|---|
| `temp/buses.csv`, `temp/lines.csv`, `temp/generators.csv`, `temp/loads.csv` | NGCP-coded PyPSA-PH-derived inputs with upstream corrections | Change only with an explicit provenance entry; preserve original meaning/units |
| `temp/loads_t.csv` | Historical hourly demand used for scenarios | Preserve source/time basis; not current telemetry |
| `load_estimates.csv` | Gap-fill demand for buses without feeder records | Does not override buses already assigned feeder demand |
| `../scripts/constants.py` | Name mappings, merge/drop rules, cable/line overrides and dispatch assumptions | Trace factual corrections and estimates separately |
| `buses.csv`, `lines.csv`, `generators.csv` | Prepared network and unit reference tables | Generated by `process_temp.py`; direct edits are overwritten by full preparation |
| `load_scenarios.csv`, `gen_scenarios.csv` | Prepared per-bus scenario overlays | Generated by full or snapshot-only preparation |
| `SOURCES.md` | Evidence, tags, historical findings and corrections | Append dated evidence; check later entries before treating an old finding as unresolved |
| `../web/public/data/` | Published model snapshots | Generated from clean/scenario tables; rebuild every affected directory |

Input code prefixes select Eastern Visayas (`04`), Cebu (`05`), Negros (`06`), Bohol (`07`) and Panay/Guimaras (`08`). These are dataset codes, not a statement about present administrative regions.

The local audit on 2026-09-05 reproduced all five prepared CSVs exactly in an isolated copy. Current counts are 54 buses, 60 lines, 115 generator units, 54 rows per scenario table and 45 load-estimate rows. Counts describe this checkout, not a complete physical grid inventory.

## Provenance and assumptions

The source ledger distinguishes **sourced** (individually verified), **pypsa-ph** (inherited) and **estimate**. Do not describe the whole dataset as independently verified merely because some fields have primary citations. The ledger has historical rows later superseded by fixes, including the original missing Cebu–Bohol link entry.

`constants.py` records the chosen modeling assumptions and citations. A comment citing a standard does not establish a particular installed cable's parameters. Transformer defaults, overhead capacitance defaults and the PV threshold are currently defined separately in `build_data.py`.

## Clean CSV schemas

### `buses.csv`

| Field | Meaning |
|---|---|
| `name` | Unique readable key used by line endpoints, scenarios and frontend selection |
| `x`, `y` | Longitude, latitude in degrees |
| `v_nom` | Display/source nominal voltage, kV; HVDC label may differ from AC model base |
| `voltages_kv` | Source voltage metadata; current filter uses `v_nom` |
| `island` | Island membership |
| `bus_type` | `substation`, `generator`, `bess` or `hvdc` |
| `is_slack` | Intended external-grid reference; Ormoc in current data |
| `p_mw`, `q_mvar` | Base active/reactive demand, MW / MVAr |
| `load_count` | Feeder count used for base demand |
| `gen_capacity_mw` | Aggregated installed generator capacity, MW |
| `gen_mw` | Estimated aggregate base dispatch, MW |
| `gen_carriers`, `primary_carrier` | Fuel metadata; primary carrier chosen by installed capacity |

### `lines.csv`

| Field | Meaning |
|---|---|
| `line_id` | Line record key |
| `from_bus`, `to_bus` | References to bus `name` |
| `voltage_kv` | Line voltage class, kV |
| `length_km` | Endpoint haversine proxy, not surveyed route length |
| `r_ohm_per_km`, `x_ohm_per_km` | Series impedance, Ω/km; inherited totals normalized by proxy length unless overridden |
| `c_nf_per_km` | Shunt capacitance, nF/km |
| `max_i_ka` | Per-circuit current rating, kA |
| `parallel` | Aggregated circuit count |
| `is_submarine`, `cable_type` | Cable classification and metadata |

The current line CSV has no `island` column. Since the frontend passes features with no island property through its filter, all lines survive island-only filtering; voltage filtering still applies.

### `generators.csv`

Unit-level reference table with bus attachment, carrier, installed capacity, build year and estimated dispatch. `process_temp.py` aggregates units into `buses.csv`; `build_data.py` reads the bus aggregate rather than this unit table directly. Installed capacity and dispatched power are distinct.

## Demand and dispatch scenarios

`load_scenarios.csv` joins on `name`, with `p_mw_{peak,mean,offpeak}` and matching `q_mvar_*`. `gen_scenarios.csv` joins on `name`, with `gen_mw_{peak,mean,offpeak}`.

- **Peak:** the hour of maximum coincident load across aligned Visayas time-series buses.
- **Mean:** each bus's annual mean; not a single simultaneous operating hour.
- **Off-peak:** the hour of minimum coincident system load.
- **DC:** uses base demand and generation from `buses.csv`, without either scenario overlay.

Demand snapshots use the historical `loads_t.csv` and the constant Q/P ratio. Dispatch snapshots apply estimated carrier factors to generator capacity. They are not measured dispatch or an optimization result. The scenario builder gives buses without time-series data zero demand; the base feeder/gap-fill estimate is not carried into those scenario rows.

AC peak/mean/off-peak build paths apply matching scenario rows when available. If the scenario table is absent, base values remain. Explicit DC ignores `--scenario` for input selection and always writes `dc/`.

## Frontend data contract

Each scenario must contain all three files under its directory:

| File | Structure |
|---|---|
| `buses.geojson` | GeoJSON FeatureCollection of Points, coordinates `[longitude, latitude]` |
| `lines.geojson` | FeatureCollection of two-point LineStrings with matching bus endpoints |
| `manifest.json` | Build metadata object |

CSV row fields pass through to feature properties. The exporter adds:

| Property | Applies to | Meaning |
|---|---|---|
| `connected` | Bus | Reachable from slack in the constructed model |
| `vm_pu` | Bus | Solver voltage magnitude, pu; missing where no result is available |
| `va_degree` | Bus | Solver voltage angle, degrees |
| `hvdc_import_mw` | HVDC bus, manifest | Slack injection proxy; positive into Visayas, negative out |
| `loading_percent` | Line | Solver current loading relative to assumed rating, % |
| `p_from_mw` | Line | Signed active power at the from end, MW |
| `i_from_ka` | Line | From-end current magnitude, kA |

Missing results are not zeros. Input NaNs are normalized by `_clean`, but solver NaNs are not consistently normalized before JSON serialization; validate regenerated outputs for non-standard `NaN`/`Infinity`, especially after disconnected-network or solver changes.

Manifest fields are `generated_at` (UTC build time), `power_flow_mode` (`AC`, `DC`, `none`), `demand_scenario`, `n_buses`, `n_lines`, `n_submarine_lines`, `total_load_mw`, `total_gen_mw`, `hvdc_import_mw` and `hvdc_capacity_mw`. Totals are across input buses, whereas interchange comes from the solved connected component. The timestamp does not identify the historical demand observation.

## Interpretation limits

The AC model introduces assumed transformers and voltage support. Ormoc's displayed 350 kV label represents the link, while AC construction uses 230 kV at that bus. Internal transformer buses are not exported. A DC fallback uses the already constructed AC network; an explicit DC build has different construction.

The slack is unconstrained: an interchange above 440 MW only prints a warning. PV Q bounds are assigned but the current solve does not explicitly enable their enforcement. Thermal and voltage alerts flag assumed-model thresholds, not confirmed violations on the operating grid. The model does not include all existing/planned facilities or the full external-grid system.

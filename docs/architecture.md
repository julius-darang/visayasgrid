# Project Architecture

## What this project is

**visayasgrid** is a static-site visualization of the Visayas transmission grid (Philippines). It takes authoritative NGCP substation and line data, runs an AC power flow study (with DC fallback) using pandapower, and serves the results as pre-computed GeoJSON files to a React/Leaflet frontend hosted on Vercel.

The core design decision is **no backend at runtime**. All computation happens offline during the build step; the frontend only ever fetches static JSON files. A secondary DC dataset is auto-generated by GitHub Actions for scenario comparison.

## Step 1 — `process_temp.py`: raw → clean CSVs

**Input:** `data/temp/*.csv` (NGCP v1 code format)  
**Output:** `data/buses.csv`, `data/lines.csv`, `data/generators.csv`

Key transformations performed in order:

1. **Region filter** — keeps only buses whose NGCP code prefix is in `{04, 05, 06, 07, 08}` (the five Visayas regions).
2. **Code merging** — `MERGE_CODES` collapses duplicate physical facilities to a single canonical bus (currently one alias: `04STARITATAP → 04STARITA`).
3. **Readable naming** — `CODE_INFO` maps each NGCP code to a human name, island, and bus type (`substation`, `generator`, `bess`, `hvdc`).
4. **Slack assignment** — the bus named `"Ormoc"` is flagged `is_slack=True`; it represents the AC termination of the Leyte–Luzon HVDC link.
5. **Load assignment** — each feeder attachment in `temp/loads.csv` is treated as `LOAD_MW_PER_FEEDER = 12 MW`. Reactive power is `Q = P × LOAD_PF_QP_RATIO = 0.30` (0.96 PF). Buses with no feeder entries are gap-filled from `data/load_estimates.csv`.
6. **Generator dispatch** — each generator unit's operating MW is estimated as `p_nom × DISPATCH_FACTOR[carrier]`. Units at the same bus are summed to `gen_mw` and `gen_capacity_mw`.
7. **Line processing** — pairs with both endpoints in Visayas are kept; voltage is parsed from the NGCP line name prefix; haversine distance is computed as a length proxy; impedance is normalised to per-km.
8. **Submarine cable override** — bus-pairs in `SUBMARINE_PAIRS` get XLPE 630 mm² parameters (`r=0.0754`, `x=0.121 Ω/km`, `c=200 nF/km`, `max_i=0.645 kA`) instead of the NGCP values divided by haversine distance.
9. **Line impedance overrides** — specific bus-pairs in `LINE_IMPEDANCE_OVERRIDES` get standard overhead-line parameters when inherited values are implausible (e.g., after coordinate corrections changed apparent length).
10. **Parallel circuit merging** — if multiple NGCP records connect the same bus-pair at the same voltage, their circuit counts are summed into a single `parallel` entry.
11. **Orphan detection** — buses with no transmission lines are printed as warnings (kept in output for map display).

## Step 2 — `build_data.py`: CSVs → load flow → GeoJSON

**Input:** `data/buses.csv`, `data/lines.csv`  
**Output:** `web/public/data/buses.geojson`, `web/public/data/lines.geojson`, `web/public/data/manifest.json`

### Network construction

A pandapower network is built at 60 Hz. The build supports two modes controlled by `--mode`:

#### AC mode (`--mode ac`, default)

- **Buses** — created with `vn_kv = v_nom`. The HVDC terminus (Ormoc) is modelled at its **AC-side voltage (230 kV)** rather than the DC link voltage (350 kV), eliminating the main voltage-base mismatch that would prevent NR convergence.
- **Cross-voltage connections** — lines between buses at different nominal voltages (e.g., 230 kV ↔ 138 kV) get an intermediate bus at the lower voltage plus an ideal transformer model, so every line operates at a single per-unit voltage base. ~17 such connections exist, creating ~11 intermediate `_trafo_*` buses.
- **Slack** — the `is_slack` bus becomes an `ext_grid` (external grid / infinite bus) at `vm_pu = 1.0`. The slack absorbs or injects whatever MW is needed to balance the system, analogous to how the HVDC link compensates Visayas imbalance.
- **Loads** — buses with `p_mw > 0` or `q_mvar > 0` get a `load` element.
- **Generators** — units with `gen_mw >= PV_GEN_THRESHOLD_MW (100 MW)` become **PV buses** (`gen`) with reactive capability (`max_q_mvar = 0.6 × P`, `min_q_mvar = -0.4 × P`) to give NR voltage support. Smaller generators are modelled as PQ injection (`sgen`, `q_mvar = 0`).
- **Lines** — created with per-km r, x, c parameters and `parallel` count. Overhead lines with zero shunt capacitance get populated from `OVERHEAD_C_NF` by voltage class (needed for AC convergence).
- **Transformers** — autotransformer parameters from `TRAFO_DEFAULTS` (NGCP TDP 2024 Annex B typical values).

#### DC mode (`--mode dc`)

- All buses keep their CSV `v_nom` (Ormoc stays at 350 kV).
- No transformer models inserted.
- All generators modelled as `sgen` (PQ injection).
- `c_nf_per_km` values come from the CSV as-is.
- Output written to `web/public/data/dc/`.
- Auto-generated by GitHub Actions on push to `main` when data/ or scripts/ change.

### Topology check

`pandapower.topology.unsupplied_buses(net)` identifies buses not reachable from the slack. These are excluded from the load flow run but kept in GeoJSON (shown as `connected: false`).

### AC load flow

`pp.runpp(net_run, algorithm="nr", init="dc", numba=False)` — Newton-Raphson AC power flow that:
- Solves both **active** and **reactive power** (MW + MVAr) on each branch
- Computes **voltage magnitudes** (pu) and **angles** (degrees) at each bus
- Handles per-unit normalisation correctly via transformer models

If AC diverges, falls back to `pp.rundcpp(net_run)` — a linearised DC power flow (same behaviour as DC mode).

### HVDC interchange capture

After load flow, `net_run.res_ext_grid["p_mw"].iloc[0]` gives the total MW injected by the Ormoc slack:
- **Positive** → Luzon importing to Visayas (Visayas demand > local generation)
- **Negative** → Visayas exporting to Luzon (Visayas generation > local demand)

This value is stored as `hvdc_import_mw` on the Ormoc bus feature and in `manifest.json`. A warning is printed if `|hvdc_import_mw| > HVDC_CAPACITY_MW (440 MW)`.

### GeoJSON emission

- **buses.geojson** — each bus becomes a `Point` feature. All CSV columns are passed through as properties (with NaN → null cleaning), plus `connected`, `vm_pu`, `va_degree`, and `hvdc_import_mw` (for the Ormoc bus only).
- **lines.geojson** — each line becomes a two-point `LineString` using bus endpoint coordinates. All CSV columns plus `loading_percent`, `p_from_mw`, `i_from_ka`.
- **manifest.json** — lightweight metadata: generation timestamp, power flow mode, bus/line counts, total load/gen MW, HVDC interchange MW, HVDC capacity.

## Step 3 — React frontend

### Data loading (`useGridData.js`)

On mount, three parallel `fetch()` calls retrieve `buses.geojson`, `lines.geojson`, and `manifest.json` from `web/public/data/`. A `cancelled` flag prevents React state updates if the component unmounts before the promises resolve. Errors in any fetch propagate to an `error` state displayed as a banner.

### Scenario selection

The frontend can load either the AC or DC dataset. The scenario is determined by URL hash or a toggle; the DC dataset is served from `web/public/data/dc/`.

### Filtering (`filterFeatures` in `useGridData.js`)

`App.jsx` maintains `selectedIslands` and `selectedVoltages` state. On change, `filterFeatures(fc, { islands, voltages })` returns a new FeatureCollection:
- Features whose `island` property is **not** in the selected set are removed.
- Features whose voltage (`v_nom ?? voltage_kv`) is **not** in the selected set are removed.
- A feature with a missing `island` property passes the island filter (shown regardless of selection).
- A feature with `v = 0` or non-numeric voltage passes the voltage filter.

Both filters are ANDed.

### Map rendering (`MapView.jsx`)

**Lines** are rendered as `Polyline` elements coloured by `colorForLoading(loading_percent)` (green `< 50%`, amber `50–80%`, red `80–100%`, dark red `> 100%`). Submarine lines render with a dashed stroke. Lines with `|p_from_mw| ≥ 30 MW` display a `▶` flow arrow at the midpoint, oriented by bearing. Hovering a line shows a sticky tooltip with voltage kV first, then loading % and MW flow.

Line colour is user-selectable via a "Colour lines by" toggle in the sidebar:
- **% Loading** (default) — green → amber → red → dark red scale keyed to thermal rating
- **Voltage kV** — same voltage palette as bus markers

**Buses** use different shapes depending on `bus_type`:

| `bus_type` | Shape | Fill colour | Size |
|---|---|---|---|
| `"generator"` | Circle (`CircleMarker`) | Carrier/fuel colour (`colorForCarrier`) | Scales logarithmically with `gen_capacity_mw` |
| `"substation"` | Square (`Marker` + SVG `divIcon`) | Nominal voltage colour | Fixed by voltage class |
| `"hvdc"` | Square + dashed violet ring | Nominal voltage colour | Fixed by voltage class |

Substation squares that carry aggregated generation (i.e. `gen_capacity_mw > 0` but `bus_type != "generator"`) additionally display a carrier-coloured outer ring when "Generator rings" is enabled — this signals blended generation until dedicated generator nodes are added to the dataset.

### Additional components

- **Sidebar** — island checkboxes, voltage checkboxes, search by name, display toggles (bus labels, flow arrows, generator rings), theme toggle, data table link.
- **InfoPanel** — click-to-inspect: bus details (load, gen, HVDC, voltage) or line details (flow results, technical parameters).
- **StatsPanel** — summary card: total demand, net, generation, HVDC interchange, overloaded lines, voltage violations, by-island breakdown.
- **Legend** — colour scale reference for voltage, loading, generator carrier rings, and per-unit voltage.
- **DataTable** — sortable table of visible buses/lines with click-to-focus on map.
- **AboutModal** — educational content about the Visayas grid, power flow, and modeling approach.

### Colour encoding (`styles.js`)

| Layer | Attribute | Scheme |
|---|---|---|
| Bus fill (substation/hvdc) | Nominal voltage | 350 kV → violet, 230 kV → red, 138 kV → amber, 69 kV → teal |
| Bus fill (generator) | Primary carrier | Coal dark, Geothermal green, Solar yellow, Wind cyan, Hydro blue, … |
| Bus fill | Per-unit voltage | Green (1.0 pu) → red (deviations), via `colorForVoltagePu()` |
| Generator ring (substations) | Primary carrier | Same carrier palette as generator circles |
| Line stroke (loading mode, default) | Loading percent | <50% → green, 50–80% → amber, 80–100% → red, >100% → dark red |
| Line stroke (voltage mode) | Nominal voltage kV | Same voltage palette as bus markers |
| Line dash | Submarine | dashed if `is_submarine` |
| HVDC bus ring | — | dashed violet outer ring |

### Performance notes (`MapView.jsx`)

`MapView` is wrapped in `React.memo` so it only re-renders when map-relevant props change (not on sidebar toggles, modal opens, etc.). Three further patterns keep hot-path rendering fast:

- **Module-level icon caches** (`_squareCache`, `_arrowCache`) — `L.divIcon` objects are created once per unique parameter combination and reused. Prevents react-leaflet from DOM-swapping all square markers on every selection change.
- **`useMemo` for topology** — `connectedSet` (the selection dim/highlight walk) and `lineCoords` (coordinate array mapping) are memoized so they only recompute when data actually changes.
- **Stable event handlers** — `lineHandlers` and `busHandlers` arrays are `useMemo`'d on the data reference, not recreated on every display toggle or selection change. This prevents react-leaflet from re-registering click listeners on every render.

## Build modes and CI/CD

### Local build

```sh
# Step 1 — rebuild clean CSVs from raw NGCP data
python scripts/process_temp.py

# Step 2 — run AC load flow, regenerate GeoJSON + manifest
python scripts/build_data.py                    # AC (default)
python scripts/build_data.py --mode dc          # DC linear

# Or chain both:
python scripts/process_temp.py && python scripts/build_data.py
```

### Automated DC build

A GitHub Action (`.github/workflows/build-dc-dataset.yml`) auto-generates the DC dataset on push to `main` when `data/**`, `scripts/**`, or the workflow file itself changes. It runs `build_data.py --mode dc` and commits the result to `web/public/data/dc/`. The AC dataset must be committed manually (requires local python/pandapower).

### Deployment

After running the build, commit `data/*.csv` and `web/public/data/*.geojson` and `web/public/data/manifest.json`, then push. Vercel redeploys automatically on push to `main`.
